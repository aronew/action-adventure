## Summary

Save points are cooling niches where the Seeker sits to rest: pressing up sets the respawn point and heals to full, and nothing else, because World state already keeps everything earned the moment it happens. A death sends the Seeker back to the last niche it sat in, seated and at full health, about 3 s after the killing hit, costing only the walk back; Continue and New game on the title screen use the same arrival. It exists so the brief's fail state ("respawn at the last save point") has a place to send the player and the save file has a way back into play.

> **Quick reference** — Layer: `Feature` · Priority: `MVP` · Key deps: `World state, Rooms and transitions, Level design, Player controller, Health`

## Overview

Save points and save/load is the part of the world the Seeker comes back to. A save point is a cooling niche in a kiln wall (region 1 lore): standing in it on the ground and pressing up makes the Seeker sit, and sitting sets the **respawn point** to that niche and heals the Seeker to full before it stands again. Sitting saves nothing else, because everything earned is already kept by World state the moment it happens (world state rules 5 and 6): a save point only moves where the Seeker comes back. When health reaches zero, the Seeker returns to the last niche it sat in, with full health, through the same fade as any arrival (rooms and transitions rule 8). Everything earned stays (world state rule 4), so a death costs the walk back and nothing else. At the title screen this system offers **Continue**, which builds the world from the save and puts the Seeker at that niche, and **New game**, which asks before it replaces a save. The player feels it as a warm place to rest before a hard stretch, never as a chore of remembering to save. Without it, a death would have nowhere to send the Seeker, a save file would have no way back into play, and level design's saves by role (rules 15 and 16) would be scenery. How the file is written belongs to World state and its storage ADR; this system owns the niche, the respawn, Continue and the title prompts. **[Owner, 2026-11-20: press up to sit; sitting heals to full; a rest moment with no "saved" text]**

## Detailed Design

### Core Rules

Tags: **[Owner]** = your decision; **[Rec]** = recommendation, change freely. `systems-designer`, `gameplay-programmer` and `engine-programmer` not consulted: Lean mode. Review manually before production.

**The save point**

1. **A save point.** A save point is an object placed in a room, with an object id (rooms and transitions rule 3), a **rest area**, an **arrival point** (rooms and transitions rule 8), a facing (the way the niche opens) and a role from level design rule 15 (boss, hub or reward) in its room data; nothing in this system reads the role, it is there for Grid map and Fast travel if they use it. The rest area is an authored rectangle of whole tiles, at most `rest_area_max_width` tiles wide (Tuning Knobs), whose bottom edge lies on a floor: solid ground under every tile of its width, with no gap in that floor and no solid or one-way tile inside the rectangle, and at least `hitbox_size.y` tall and at least `hitbox_size.x` wide (`player_config.tres`, 22 by 10 px today, so 4 by 2 tiles of 6 px; read, never copied) so the Seeker can stand in it. The arrival point is the **seat**: a point on that floor, inside the rest area, where the Seeker sits for every rest and every arrival (rules 3, 8). The Seeker keeps its standing hitbox while seated (the sit and stand poses are visual), so the **seat box**, the hitbox centred on the seat with its feet on the floor, is what must fit. The room check rejects a save point whose arrival point lies outside its rest area or off its floor, or whose seat box holds a solid or one-way tile or lacks ground under any part of its width (a seat within 5 px of a wall), and a rest area that is wider than the cap, narrower or shorter than the hitbox, has a gap in the floor under it or holds a solid or one-way tile. A save point has no state of its own in World state: it raises no flag, and whether it was ever used is not recorded. Only the respawn point names it. A cooling niche is a save point only when its room data gives it a rest area; a niche without one is scenery (the Carrier's Kiln's niche in the region 1 lore is scenery, rule 3). **[Rec; Owner, first review 2026-11-20: the arrival point is the seat; the Kiln's niche is scenery. Second review 2026-11-20: width cap of 3 tiles; the room check also covers the rest area's floor, contents and height. Fourth review 2026-11-20: width at least the hitbox's, a clear seat box, the standing hitbox while seated]**
2. **Sitting.** Pressing `interact` (bound to W, Up, D-pad up and gamepad B in `player_input_bindings.gd`; called "up" below) while the Seeker's sensor overlaps the rest area, on the ground (the controller's ground state: not crouching), not attacking and not in hurt lock, and with its feet within one tile (`collision_tile`, 6 px) above or below the seat's floor, starts a **rest**. The feet condition keeps a Seeker standing on a step beside the niche, whose 22 px sensor still overlaps the area, from being moved up or down the wall (rule 3). The other conditions and the detection are those of entering a door (rooms and transitions rule 7; `player.gd` finds a door by the sensor overlapping its area, `_find_overlap`). Up on the ground already means other things to the controller (a door, an exit, a climb: `_try_start_climb` starts on up while a `climbable` overlaps, and `_state_ground` would hand the press to a rest first), so a rest area may not overlap a door's area, an exit, a `climbable` or any later object that uses up (Edge Cases). Nothing else starts one: walking, falling or dashing through the rest area does nothing. While the sensor overlaps a rest area, up does not select the up attack, as on a door (`player_combat.poll`'s `on_door`): attack with up held is the ground attack, and up alone is `interact`. Gamepad B is `interact` too and starts a rest the same way; it never selects the up attack or a climb, which read the up axis. Left-stick up is the `move_up` axis and `interact` has no axis binding, so stick up does not start a rest, just as it does not enter a door; the D-pad and B do (UI Requirements). **[Owner, 2026-11-20: press up to sit; Rec: door detection; third review 2026-11-20: B named; fourth review 2026-11-20: the feet condition; stick up]**
3. **A rest.** On the accepted press the Seeker's x and y are set to the seat (rule 1; the bound is below), its velocity to zero and its facing to the save point's facing, as a door sets the Seeker's x to the door's (`_start_enter_door`); so a rest and an arrival sit on the same spot. **The snap bound:** a press is accepted on sensor overlap and the sensor is the hitbox (`hitbox_size`, 10 by 22 px), so the Seeker's centre can lie up to `hitbox_size.x / 2` (5 px) outside the rest area, and the sideways move is at most `rest_area_max_width` tiles plus that half width: under 23 px at the 3-tile cap (6 px tiles, `collision_tile`), under 29 px at the knob's maximum of 4. The vertical move is at most one tile (6 px), because rule 2 refuses a press from further above or below the seat's floor. It is a short shuffle and never a jump: the Seeker's body already overlaps the empty rest area when the press is accepted and the seat box is clear (rule 1), so the move crosses no wall and leaves the Seeker in none. It sits (`sit_time`), holds still for `rest_hold_time` while the rest moment plays (Visual/Audio), then stands (`stand_time`). All input but pause is ignored for the whole rest, and pause freezes it. The Seeker cannot be hurt or killed from the accepted up press until the stand-up ends, as during EnterDoor (rooms and transitions rule 7); enemies, hazards and projectiles keep running, and their contact does nothing. Control returns on the frame the stand-up ends (Formulas F1). **[Owner, first review 2026-11-20: snap to the seat; third review 2026-11-20: bound restated; fourth review 2026-11-20: y set too, Owner: set y to the seat]**

   Because a rest is an invulnerable full heal, no fight may reach a rest area. Three placement requirements on Level design, checked on the room data, not rules at the niche: (a) no enemy's leash bound (level design rule 24, F7) overlaps a rest area; (b) no enemy spawn point of any type (a projectile source's included) and no hazard lies on any screen the rest area touches (rooms are whole screens, rooms and transitions rule 1). A **hazard** is anything that damages or kills the Seeker on touch or on entering it: floor hazards such as spikes, a kill plane or a pit that has one, and moving hazards; level design owns the placement check and the Combat story's hazard group is its source once it exists. A reward save (level design rule 15) therefore keeps the hazards that guard its route on neighbouring screens, never on its own. This keeps flyers, boss adds and spawned hazards away until their own GDDs give them a bound to check; (c) no rest area lies in an **arena**: a boss or mini-boss room that locks when its fight starts, or, in a large room, the camera zone that fight locks to (rooms and transitions rule 14). A save beside an arena (level design rule 15: the room before it, an antechamber, or a save section of a large room) stays allowed. A projectile that crosses a resting Seeker does nothing (above); that is accepted, not checked. **[Owner, 2026-11-20: safe while seated; rely on placement. Owner, first review 2026-11-20: no spawn or hazard on the rest area's screens]**
4. **What a rest does.** On the frame the up press is accepted, two things happen and nothing else: the respawn point is written to World state as (room id, save point object id), and health is set to `max_health` (`player_config.tres`, read, never copied). Both happen at the start of the rest, so a quit or crash during it loses neither (world state rule 6 commits at the end of that frame). Sitting again at the save point already held is not a change to the record (world state rule 5) but still heals. No flag is raised, no enemy is reset and the room is not rebuilt. **[Owner, 2026-11-20: heals to full; Rec: at the start of the rest]**
5. **No manual save.** There is no save command and no save menu. World state keeps every change the moment it happens (world state rules 5 and 6); a save point only moves where the Seeker comes back. **[Owner, 2026-11-20: world state owns the durable write]**

**Death and respawn**

6. **Death.** On the frame `PlayerHealth.depleted` fires, controls lock, the Seeker plays its death clip and from then on it cannot be hit and triggers no object it touches: no pickup, pass line, exit, door, rest area, boss or arena-lock trigger, shortcut trigger or any later trigger (Edge Cases). When the death clip ends (`died`) and `death_hold_time` has passed (Formulas F2), a respawn is requested from Rooms and transitions (rule 8 there) to the respawn point's room and arrival point. **[Rec; Owner, 2026-11-20: `death_hold_time` starts at 0]**
7. **What a death costs.** Only the walk back. Death changes nothing in World state (world state rule 4), and the respawn point is not rewritten. The arrival room is built fresh (rooms and transitions rule 12), so its enemies are back and an unbeaten boss is unbeaten; every other room rebuilds its enemies when it is next entered. The one exception is an enemy World state keeps dead (rooms and transitions rule 12; world state Open Questions 3): region 1's tutorial Waster "never returns" and stays gone after a death. **[Owner, 2026-11-20: only the walk back; third review 2026-11-20: stays-dead exception]**
8. **Arrival.** After a death, a Continue or a new game, the Seeker arrives at the save point's arrival point **seated**, with zero velocity, full health and the save point's facing, then stands up (`stand_time`); control returns when the stand-up ends (Formulas F2). It cannot be hurt or killed from the death, or the load, until the stand-up ends. All input but pause is ignored from the death, or the load, until the stand-up ends, including the presses Rooms and transitions buffers from the freeze to the first frame of the fade-in (its rule 9): for an arrival with no exit they are discarded, not delivered, so a button mashed while dying neither jumps, attacks nor starts a rest when control returns. Rooms and transitions rule 8 says an arrival is "standing", so it needs revising to allow a seated arrival at a save point (Dependencies). Pause works as in play: it freezes the death clip, the hold and the stand-up where they are, so control returns later by the paused time; during the transition itself the pause opens on the first frame after the fade-in ends (rooms and transitions Edge Cases). **[Owner, 2026-11-20: seated, then stands up; fourth review 2026-11-20: pause freezes every timer]**
9. **Where the respawn point comes from.** The respawn point is the one in World state. A new game writes the region's **start save point** (region 1: the Waking Niche, the start room's save point in the lore) as the respawn point once World state has committed its empty record, so in normal play the record always holds one. That is two commits, the empty record and then the respawn point; a crash between them leaves a record with no respawn point, which the next fallback handles, so the window is accepted **[Owner, second review 2026-11-20]**. Each region's data names its start save point. If the record holds no respawn point (a save from before this rule, or a damaged one), the Seeker arrives at the start save point of region 1. If it names a save point no longer in its room, the Seeker arrives at the start save point of that room's region. If it names a room that was cut, the room's data is gone, so its region is read from the record Rooms and transitions keeps for a retired room id (its rule 3 reserves the id; a region in that record is a requirement on it, Open Questions); with no such record, the Seeker arrives at the start save point of region 1. Either is the "region's first save point" of rooms and transitions Edge Cases. **[Owner, 2026-11-20: respawn set to the Waking Niche; Rec: the fallbacks]**

**Continue and new game**

10. **The title screen's two choices.** Continue is offered when World state reports a save it can load (its file table: Current, Older, or Unreadable with a readable last good copy). When it cannot, Continue is shown unavailable with World state's message (the save needs a newer version; the save cannot be read), and when there is no save at all it is not shown. Both choices wait until World state's commit chain is idle (world state rule 8). **[Rec]**
11. **Continue.** World state loads the record before the first room is built (world state rule 8), then the Seeker arrives at the respawn point (rules 8 and 9) with full health: health is not in the record (world state rule 1), so every Continue starts full. **[Rec]**
12. **New game.** When a save exists (any file state but None), New game first asks whether to replace it, with No selected. For a newer or unreadable save it shows World state's warning instead and World state makes its kept copy first (world state Edge Cases). Once confirmed, World state starts and commits the empty record, this system writes the start save point as the respawn point (rule 9), and the Seeker arrives there seated (rule 8). With no save, New game starts at once. **[Rec; world state rule 7: Save points owns the prompt]**

### States and Transitions

The Seeker, as this system sees it:

| State | Meaning | Enter when | Leave when |
|---|---|---|---|
| Playing | Normal control | The game starts play; a rest's stand-up ends; an arrival's stand-up ends | `interact` accepted in a rest area (rule 2): to Resting. `depleted` fires: to Dead |
| Resting | Sitting, holding, standing; input locked but pause; cannot be hurt | From Playing (rule 2). The respawn point and the heal are applied on entry (rule 4) | The stand-up ends: to Playing. Nothing else leaves it: a rest is never cut short |
| Dead | Death clip, then the hold; input locked; cannot be hit; triggers nothing it touches | From Playing (`depleted`) | The death clip ends (`died`) and `death_hold_time` has passed (F2): the respawn is requested and Rooms and transitions runs the transition (its rule 9): to Arriving |
| Arriving | The transition, then seated at the arrival point, then the stand-up; input locked but pause, buffered presses discarded (rule 8); cannot be hurt | From Dead; or Continue or a confirmed new game starts play | The stand-up ends: to Playing |

Resting cannot be entered from Dead or Arriving, and Dead cannot be entered from Resting or Arriving, because the Seeker cannot be hurt in either (rules 3 and 8). Grid map opens its map only in Playing (grid map rule 11).

## Formulas

`systems-designer` lens applied in this session (lean mode spawns no agent): every variable was put at its minimum, its maximum and 0; nothing divides, nothing goes negative and no input makes another inert. No feedback loop: nothing accumulates, so resting or dying never feeds back into anything. The one degenerate use found, an invulnerable full heal next to a fight, is closed by placement (rule 3, owner). Clip times are measured from `src/player/seeker_animations.json`, never copied into data.

### F1. Rest time

The rest_time formula is defined as:

`rest_time = sit_time + rest_hold_time + stand_time`

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| sit_time | float (s) | 0.20 today | calculated (sit clip length) | The sit clip; `crouch_down` (4 frames, 200 ms) stands in until a sit pose exists (Visual/Audio) |
| rest_hold_time | float (s) | 0.5-2.0, starts at 1.0 | data file | The rest moment: ash settles, the Seeker's shade warms a half-step **[Rec]** |
| stand_time | float (s) | 0.10 today | calculated (stand clip length) | The stand clip; `crouch_stand` (1 frame, 100 ms) stands in. Also ends every arrival (F2, rule 8) |

**Output Range:** 1.30 s at the starting values; 0.80-2.30 s across the `rest_hold_time` range. Below 0.5 s of hold the rest moment cannot be seen; above 2.0 s it is a wait the player notices, against "saving is invisible" (Game Feel). The Seeker cannot be hurt for all of `rest_time` (rule 3).
**Example:** the Seeker presses up in the Waking Niche: 0.20 s sitting, 1.0 s resting, 0.10 s standing; control returns 1.30 s after the press, with the respawn point and the heal applied on the press frame (rule 4).

### F2. Death to control

The death_to_control formula is defined as:

`death_to_control = death_clip_time + death_hold_time + transition_time + stand_time`

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| death_clip_time | float (s) | 2.41 today | calculated (death clip length) | The `death` clip, 20 frames ending in a 0.90 s held frame; the Player controller emits `died` when it ends |
| death_hold_time | float (s) | 0-1.0, starts at 0 | data file | Pause after the clip before the respawn is requested. Starts at 0 because the clip's last frame already holds 0.90 s; the code's stand-in `RELOAD_DELAY` is 1.0 **[Owner, 2026-11-20: starts at 0]** |
| transition_time | float (s) | 0.2 or more; 0.45 at R3's starting values | rooms and transitions R3 (registry `transition_time`) | The fade out, any load still needed, the build and the fade in |
| stand_time | float (s) | 0.10 today | as F1 | The arrival's stand-up (rule 8) |

**Output Range:** 2.96 s into a resident room (2.41 + 0 + 0.45 + 0.10) at the starting values (about 3.2 s with this container's measured `build_time` of 0.33 s; see Timing in tests); about 3.88 s into a room that must load first (R3's example, 1.37 s). At `death_hold_time` 1.0 these become 3.96 and 4.88 s. The Seeker cannot be hurt for all of it (rules 6, 8). The same arrival, without the death clip and hold, ends a Continue and a new game: `transition_time + stand_time`.
**Data file and check:** `rest_hold_time`, `death_hold_time` and `rest_area_max_width` live in `src/save/save_point_config.tres`, a `SavePointConfig` resource **[Rec]**. Its `validate()` returns the name of every value outside its range; it runs when the config loads at boot, and a non-empty result stops the game before the title screen and names the values, so a bad number never reaches play. **[Owner, 2026-11-20: rejected at load]**

**Timing in tests:** `transition_time` holds a measured `build_time` (R3; about 0.33 s in this container against a 0.10 s budget), so the F2 figures hold only at R3's starting values. Engine tests check control returning at `death_clip_time + death_hold_time + transition_time + stand_time` with `transition_time` as Rooms and transitions reports it for that transition, not at a fixed 2.96 s.

**Example:** the Seeker dies in a hub two rooms from its last niche, whose biome is resident: the death clip plays for 2.41 s, the respawn is requested at once, the transition takes 0.45 s, the Seeker appears seated at the niche and stands in 0.10 s; it moves again 2.96 s after the killing hit.

## Edge Cases

`systems-designer` not consulted: Lean mode. Review manually before production.

**Sitting**
- **If up is pressed in a rest area while airborne, attacking or in hurt lock**: nothing happens and nothing is buffered; a press once the conditions hold starts the rest (rule 2). **[Rec]**
- **If up is pressed while crouched in a rest area**: nothing happens, as for a door; standing up and pressing again starts the rest (rule 2). **[Rec]**
- **If up is pressed with the sensor just overlapping the rest area's edge**: the rest starts and the Seeker is moved to the seat (rule 3); the snap is at most the rest area's width (at most `rest_area_max_width` tiles) plus half the hitbox width (5 px) sideways and one tile up or down, the bound of rule 3. Inside the area the floor is whole and empty and the seat box is clear (the room check, rule 1), and the Seeker's body already overlaps the area, so the move never crosses a wall and never leaves the Seeker in one. **[Rec; Owner, second review 2026-11-20: width cap; third review 2026-11-20: half hitbox added; fourth review 2026-11-20: y added]**
- **If up is pressed in a rest area while standing on a step more than one tile above or below the seat's floor** (its sensor still overlaps the area): nothing happens and nothing is buffered, as when airborne; the Seeker steps to the niche floor and presses again (rule 2). **[Rec; fourth review 2026-11-20]**
- **If the player mashes buttons while dying or arriving**: every press is ignored until the stand-up ends, and presses Rooms and transitions would buffer to the fade-in are discarded (rule 8), so nothing fires at control return. **[Rec]**
- **If a hit lands on the same frame as the up press**: the hit is resolved first. If it starts hurt lock the press is refused; if it brings health to zero the Seeker dies and no rest starts, so the respawn point is not written. The Seeker is safe only from the accepted press on (rule 3). **[Rec]**
- **If a rest area overlaps a door's area, an exit, a `climbable` (a ladder) or any other object that uses up**: up would mean two things (a ladder climbs on up, `_try_start_climb`), so the room check rejects the room and names it. A requirement on the rooms and transitions room check. **[Rec; second review 2026-11-20: ladders added]**
- **If the game is paused, quit or crashes during a rest**: the respawn point and the heal were applied on the press frame (rule 4) and the respawn point is committed at the end of that frame (world state rule 6), so a Continue arrives at that niche. Pause freezes the rest where it is. **[Rec]**
- **If the Seeker sits at the save point already held**: the record does not change (world state rule 5), health is set to full and the rest plays in full. **[Rec]**

**Death and respawn**
- **If the dead Seeker's body slides into a pickup, a gate's pass line, an exit, a door, a rest area or a boss or arena-lock trigger** (death knockback, a moving platform): none of them trigger (rule 6), so nothing is raised by a dead body and no fight starts. What is on screen while it dies still counts as seen (level design States), because seeing is not touching. **[Rec]**
- **If the Seeker dies on the frame a flag is raised**: the flag stays raised (world state rule 4 and Edge Cases); this system adds nothing. **[Rec]**
- **If the Seeker falls onto a kill plane or a hazard brings health to zero**: it is a death like any other (rule 6). **[Rec]**
- **If the Seeker dies in a locked boss arena**: it arrives at its last niche (level design rule 15 puts one before the arena). The arena room is built fresh when it is next entered, so an unbeaten boss is unbeaten and the arena unlocked (rule 7; level design: "a locked arena never traps without a respawn"). **[Rec]**
- **If the Seeker dies in the room that holds its respawn point**: the room is rebuilt fresh on arrival, the same as any other (rooms and transitions rules 8, 12), so its enemies are back (an enemy World state keeps dead stays gone, rule 7) and unsaved breakables are whole. **[Rec]**
- **If the respawn room's biome is not resident**: the transition waits for the load behind the dark screen, with the loading mark after `load_wait_notice` (rooms and transitions R3, rule 10); F2 grows by the wait. **[Rec]**
- **If the Seeker dies before any rest in a new game**: the respawn point is the start save point (rule 9), so it arrives in the Waking Niche. **[Owner, 2026-11-20]**
- **If the respawn point names a save point that no longer exists (removed, or turned into scenery by dropping its rest area), a room that was cut, or nothing at all**: rule 9's fallbacks apply (the region's start save point; for a cut room, the region in its retired-id record, else region 1's; region 1's for an empty one). The record is not rewritten by the fallback; the next rest writes a valid point. **[Rec]**
- **If the game is paused during the death clip, the hold or an arrival's stand-up**: every timer stops and control returns later by the paused time; during the transition the pause opens after the fade-in ends (rule 8). **[Owner, fourth review 2026-11-20]**
- **If the Seeker would die during a transition or an arrival**: it cannot; it cannot be hurt from the death or the load until the stand-up ends (rule 8), and Rooms and transitions blocks damage through every transition. **[Rec]**

**Continue and new game**
- **If there is no save at all**: Continue is not shown and New game starts at once, with no prompt (rules 10, 12). **[Rec]**
- **If Continue or New game is pressed again after a choice was accepted**: the title screen ignores input from the accepted choice until the arrival's stand-up ends, so a double press starts one load, never two. **[Rec; second review 2026-11-20]**
- **If New game is chosen while a save exists and the prompt is declined**: the title screen returns with nothing changed. **[Rec]**
- **If New game is confirmed over a newer or unreadable save and World state cannot make its kept copy**: World state does not start the new game and says why (world state Edge Cases); the title screen stays, and no respawn point is written. **[Rec]**
- **If the new game's first commit fails**: World state's failure handling runs (retry cadence, "not saved" mark); this system still writes the start save point as the respawn point, which waits as pending with the empty record (world state rule 6). **[Rec]**
- **If Continue loads the last good copy** (the main file was unreadable): the Seeker arrives at that record's respawn point, which may be an earlier niche than the one last used; nothing else differs (world state States). **[Rec]**
- **If Continue or New game is chosen right after a quit to the title**: both wait, with the loading mark, until World state's commit chain is idle (world state rule 8). **[Rec]**

## Game Feel

- **Resting is a breath, not a menu.** About 1.3 s (F1), one button, no prompt and no text. The player rests because it is warm and safe, not to protect progress, which is already kept. **[Owner, 2026-11-20]**
- **A death costs the walk back, quickly.** Control returns about 3 s after the killing hit into a resident room (F2); the Seeker is back on its feet at a place it chose, with everything it earned. **[Owner, 2026-11-20: only the walk back; `death_hold_time` starts at 0]**
- **Coming back looks like waking.** Every arrival is the same stand-up from the niche, so a death, a Continue and the very first moment of a new game feel like one place. **[Owner, 2026-11-20]**
